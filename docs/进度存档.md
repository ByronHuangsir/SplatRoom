**第三轮补记（2026-09-21）**：用户报「**移动、缩放时画面会收缩到左下角，在上部、右部产生黑色空间**」——
**是我引入的回归**。根因：`src/shaders/blit-shader.ts` 的 final blit 是**逐 texel 1:1 拷贝**
（`texelFetch(srcTexture, ivec2(gl_FragCoord.xy))`），在"主目标尺寸 == 画布尺寸"时正确，而降级会把主目标缩小
（896×537 vs 画布 1280×767）⇒ 画面 1:1 落在左下角、其余取越界 texel（clamp 成黑/拖边），与描述逐点吻合。
实测（降级态）：亮像素 **31.4% → 64.5%**（静止参照 76.3%）、右侧黑边 **25 px → 0**、右上象限亮像素
**40.2% → 93.5%**（静止 92.7%）。修法：blit 新增 `uniform vec2 blitScale`（源/目标），
`ivec2(floor(gl_FragCoord.xy * blitScale))`；**`blitScale=(1,1)` 与旧代码逐 texel 等价** ⇒ 正常路径不变。
`verify-motion-quality.cjs` 扩到 **10/10**（新增"降级态画面仍铺满画布"：实测边距 0/0 px、亮像素 57.7%）。
顺带修好 `pixelScale ≠ 1` 的同一问题。详见 `docs/perf/交互期降级-实现与实测.md` §6.6。

**第四轮补记（2026-09-21）**：用户报三件事，本轮修掉第 1 件（他标注"比较严重"）：
**快速旋转时排序错误 —— 背面内容跑到前面**。根因有两层，都实测到了：
① **自家排序派发路径早就彻底死了**：`dispatchSort` 用 `ws._sortInFlight` / `ws._pendingCamera` 合并，
   而这两个字段**在本机引擎 2.21.3 里不存在**，第一次派发把标志置 true 后**没人清** ⇒ 之后每次派发
   只写进 `_pendingCamera`、永不发 worker 消息（实测 3 秒快转：调用 2 次 / `postMessage` **0** 次 /
   完成事件 **0** 次）⇒ 顺序冻结 ⇒ 背面盖住前面；
② 闸门原按固定 800 ms 放行，快转时 800 ms 内相机能转很大角度。
修法：改用自家在飞标记（`_sortPendingSince` + `sorter.on('updated')` 清零 + 3 s 超时）与自家待办位姿，
闸门改成"**不早于 200 ms + 不在飞 + 自上次派发转过 >2.5°（或位移 > 半径 1%）**"。
实测：3 秒快转派发 **0 → 30**、完成 **0 → 15**；20M fill 上相邻派发间隔 **54–172 ms**。
**代价（如实）**：20M fill、4 秒快转，帧 p50 不变（70.9 ms）但 **p95 75.9 → 154.8 ms**（排序变勤 ⇒
~80 MB 上传次数变多）；用户明确说排序错误比卡帧严重，故先保正确性。
`verify-motion-quality.cjs` 扩到 **11/11**（新增"快转期间必须在派发排序"与"派发次数有界"两项护栏）。
**另两件已定位、本轮未改**：范围滑块"只能收缩"是**结构性**的（面板两个方块同时带动 core 与 outer，
两者之间的"带"永远为空 ⇒ 框外扩展不可能；实测向外推 8506→8506、向内推→174）；
选择工具移动时的"右上方虚影"候选是"用整幅画布尺寸算屏幕坐标、画进缩小目标"的某个 pass，

**第六轮补记（2026-09-21，3.23.13）**：用户复报"快速旋转时依然会出现排序错位，短暂停留后会消失"（批准
滑块方案那一轮）。本轮把**排序残影的最后一半**做掉了，并**顺带定位并修掉用户早前报的"选区右上方虚影"**。

1. **顺序延迟补偿（已实现 + 已量化）**：派发给排序 worker 的相机位姿从"当下"改成"**落地时刻**"——
   按实测延迟 λ 沿速度外推。20M fill 夹具上顺序误差 `disp`（0 = 完全正确，0.333 = 随机）：
   **正常拖拽 125°/s：0.123 → 0.035（−71.5%）**；**猛甩 375°/s：0.284 → 0.156（−45.1%）**；
   停手后 0.00046（度量自检）。帧成本与派发频率都不变。
   实现要点：λ 取 `postSort` → `sorter.on('updated')` 的滑动平均（实测 **155~163 ms**）；
   速度用 **120 ms 时间窗**（单帧差分版只能降到 0.150，窗口版 0.087）；旋转矢量在外推前做 EMA（换向自动抵消）；
   **停手补帧不外推**（静止帧要精确）；逃生开关 `window.__SPLATROOM_SORT_PREDICT__ = false`。
   护栏 `docs/verify/verify-sort-predict.cjs`（**7/7**）。详见 `docs/perf/交互期降级-实现与实测.md` §6.9。
2. **同轮查出并修掉三个"闸门把自己锁死 / 空转"的问题**（都是用户那条"依然错位"的候选根因）：
   ① 引擎的 `sorter.setCamera` **不带 `forceUpdate`**，worker 认为"没动够"就 `return` **不回包** ⇒
   我们标的"排序在飞"永远不清 ⇒ **3 s 超时之前一次都派发不出去**（实测小夹具快转 1.5 s：post **0** 次）；
   改成两条路都走自家 `postSort`（带 `forceUpdate: true`）后，20M 上 λ 从 **372 ms 回到 155 ms**。
   ② **"相机停了"这一帧可能永远不来**（按需渲染 + 松手后无指针事件）⇒ 小模型/不降级场景下停手补帧
   与"消费排序结果"都发生不了（实测快转结束后 1.2 s 内 post **0** 次）；现在手势期间挂一次性定时器。
   ③ **排序在飞也必须出帧**（结果是异步回来的），`scene.ts` 的强制出帧条件加了 `Splat.sortInFlight`。
3. **"选区右上方虚影" = 降级踩到体积形状的 `targetSize`**（§6.10）：`BoxShape`/`SphereShape` 的片元
   着色器用 `gl_FragCoord / targetSize` 反推世界射线，而那个 uniform 填的是**画布**尺寸 ⇒ 渲染目标缩小后
   网格/棱线被画成错位的重影。改成 `scene.camera.targetSize`（含降级 override）。
   像素级口径 `docs/probes/shape-ghost.cjs`：最差瓦片色差 **方块 140.8 → 16.6**、**球体 58.9 → 15.8**
   （对照"无形状"5.8）；即在"体积形状 + 降级"下的额外差异 **+135.0 → +10.8**。
4. **两个测量坑（已记进 HANDOFF 28/29/30 条）**：`sorter.centers` 被 transfer 给 worker，主线程读到的是
   detached 数组（用它算深度全 NaN ⇒ 会得出"顺序永远是错的"的错误结论）；"派发方向 vs 落地方向"的夹角
   不能当指标（worker 合并消息，配不上对）。**新口径**：`disp` = 排序表内次序 vs 真实深度次序的平均归一化秩差。

**改法**（**不碰 splat-transform 本身，只在它之上包一层**；全部在 `src/splat/splat-serialize.ts`）：

1. **`buildViewerTemplate()` / `getViewerTemplate()`** —— 用一个"1 个高斯点"的假 `DataTable`

   `activeProgressRenderer` 就是为它加的）。
2. **`renderViewerDocument()`** —— 按 `renderViewerHtml` 的**同一批接缝**

3. **`Base64RelayWriter` + `Base64RelayFileSystem`** —— `.sog` 仍由 `writeSource` 的 `sog-bundle`

4. **`writePackagedViewer()`** —— 打包（zip）同样处理：`.sog` 直接流式写进 zip 条目，不再先过一遍

**打包版端到端探针**（用户实际运行的就是这个）：`_tmp\packaged-range.cjs` —— 用
`SplatRoom.exe --remote-debugging-port=9222 --remote-allow-origins=* --gpu=webgpu` 起来，
`puppeteer.connect({ browserURL: 'http://127.0.0.1:9222' })`，从 `http://127.0.0.1:3999/scan.ply`
（脚本自带 CORS 文件服务）导入模型再驱动界面。

**两个反复踩的编码坑**：不要用 PowerShell 的 `Get-Content` / `Set-Content` 往返 CJK 源码文件
（会把注释烧成乱码，`editor.ts`、`splat.ts` 都中过招，**第四十六轮又写坏过一个探针的注释**）；
要用 read/write/edit 工具，或 `[System.IO.File]::WriteAllText(..., UTF8Encoding($false))`。
