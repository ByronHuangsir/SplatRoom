## 0. 本轮（3.8.0）交付了什么：单轴两个滑块 → 三轴双柄 range

用户原话：*"不用最近、最远单独设滑块，直接按照'最近-滑块1----滑块2-最远'这样来布局，滑块1和滑块2中间的部分
就是选择的部分。在此基础上，可以做 3 个'最近---最远'、'左---右'、'上---下'三个，分别对应深度、左右范围、上下范围。"*

- **新控件** `src/ui/range-slider.ts`：自建双柄 range（PCUI 只有单柄）。两柄之间用高亮色填充 = 选中的部分；
  拖柄 / 点轨道 / 方向键都能改；写入时 `updating` 守卫，`Number.isFinite` 兜底 NaN。
- **浮条** 改成竖排三行 + 重置：`#selection-range-bar`（标题「选区范围」），三行 = 最近|最远、左|右、上|下。
- **语义**：深度 = 占**模型**沿手势视轴深度范围的百分比；左右/上下 = 占**手势自己的选区框**的百分比；
  三轴默认都是 0/100 = 完整穿透。三个轴都能**实时重切**当前手势（同一个历史条目）。
  新增 `selection.screenRange` / `setScreenRange` / `resetRange` 三个事件 + 4 个 localStorage 键。
- **实测**（93 万点 / WebGPU / 同一个手势上实时重切）：拉框 25–75% 三轴整段 61 ms 选中 463,306；
  深度最远→50 = 58,933（45 ms）；深度最近→25 = 31,837（46 ms）；左右→30–70 = 18,344（42 ms）；
  上下→30–70 = 1,544（46 ms）；重置回 463,306。
- **坑**：`selection.depthRange` 的返回形状一度从 `{near,far}` 改成 `{low,high}`，浮条还按 `{near,far}` 解构 →
  `undefined` → NaN → 填充条变 `NaN%`、数值框空白（`Number('') === 0` 于是看起来像 0），拖柄还会选错柄。
  公开形状保持 `{near,far}`，控件内加有限性兜底。
- **验证**：`verify-selection-depth-bar.cjs` 15 项（含**真实鼠标拖柄**：左→35 / 右→65 / 上→25 / 最远→50）、
  `verify-selection-range.cjs` 17 项（三轴实时裁剪，按索引集合验证真子集：x 30-70% 留 155/367、
  y 留 168/367，比例 42.2% / 45.8% 与 40% 带宽相符）；全量 32 套 + diag 0 失败；语言键 684（9 语言同步）。
- **打包版端到端**（3.8.0 exe / WebGPU / 93 万点 / 真实鼠标拖柄）：面板 296×147，三行标签
  `最近|最远`、`左|右`、`上|下`，拉框 33 ms 选中 309,717；最远→50 = 32,724；最近→25 = 21,945；
  左→30 = 20,176；上→30 = 2,600；重置 → 309,717 且六个数回 0/100；无控制台错误。

## 1. 上一轮（3.7.9）交付了什么

对应用户原话：*"选择工具默认穿透整个模型完整选择，然后通过调节 最近-----最远 两侧的滑块，来精确命中整个穿透空间的某一部分…
建议将选择覆盖范围和选择深度功能去掉，直接移植它的这个功能。"*

- **选择工具默认穿透整个模型**：矩形/套索/多边形/2D 笔刷/单击 / 快速填充，全部走同一个 CPU 判定
  （`src/splat/selection-range.ts`：投影全部高斯 → 2D 区域 → 沿手势视轴的深度范围），**不读深度 pass**。
- **「选区深度」浮条**（`src/ui/selection-depth-bar.ts`）：`最近 [====] 最远 [====] 重置`，默认 0 / 100 = 整段；
  拖动**实时重切当前选区**；`最近` 越过 `最远` 顶开对面那个柄；非默认时标题高亮。
  范围 = 占模型自身深度范围的百分比，按**手势当时**的视轴量取 → 正面拉框、侧面观察、拖滑块切的是同一块世界空间板层。
  （3.8.0 已把它扩成三轴双柄，见第 0 节。）
- **删掉**：`selection.useDepth`（选择深度）、`selection.footprint`（选择覆盖范围）两条状态线 + 设置面板三行 +
  底部工具条两个模式按钮与 4 个 SVG + 快捷键 `N` / `Shift+M` + 快捷键弹窗两条 + 6 个语言键 +
  屏幕路径上的 id 拾取 / footprint 加宽 / 深度回读（`src/splat/selection-band.ts` 删除）。
- **新增 `SelectRangeOp`**（`src/core/edit-ops.ts`）：`pre` / `post` / `applied` 三个快照，可原地重放，
  拖滑块不刷历史（只清 `pre` 会留下上一次的行 —— 这个坑写在注释里了）。
- 套索/笔刷路径的画布 alpha 改成**一次读出**（旧路径每个候选高斯一次 `getImageData`）。

**验证**：全量 **34 套 0 失败**（webgpu + webgl2），`npm run check` 干净。
新增 `verify-selection-range.cjs`（12 项）、重写 `verify-selection-depth.cjs`（13 项）与
`verify-selection-depth-bar.cjs`（10 项）；`verify-selection-toolbar.cjs` 改为断言旧按钮/旧 API 已消失。
顺带修好 `floater-scale` / `cluster-filter`（它们的"打开去浮云面板"代码是 3.7.7「默认关闭」之前的写法，
**那一轮之前就是红的**）。

## 2. 待办（按我建议的顺序）

1. **`src/splat/splat.ts` 里约 29 行中文注释是乱码**（更早某次 PowerShell 往返留下的；3.7.9 已修
   `src/app/editor.ts` 同源的 10 行）。代码没问题，但注释读不通了，需要按代码语义重写一批。
   另有 4 行在 `scripts/dev-history/snippets/timeline-panel_15-28.ts`（低优先）。
2. **球刷要不要接入三轴范围？** 现在是**故意不接**：球刷是贴着被打中表面往里长板层，有自己的
   「大小/厚度」两个滑块；默认整段穿透会让"在墙上刷一笔"顺手选中整间屋子后面的东西。等用户拍板。
3. **球体/盒体选择要不要也接左右/上下？** 现在也不接（它们本身就是三维体，尺寸由 gizmo 改）。
4. **D 项：选区扩边 / 收边**（用户提过、已推后四次）：两个滑块 = 沿视线的厚度（复用现在的深度带语义）
   + 世界半径膨胀（需要一张空间网格做最近邻查询）。
5. **对比工具的浮云检测器**（`src/compare/compare-analysis.ts`）：仍是旧的四信号实现、自带一份
   `estimateCellSize`，没跟 `src/splat/floater-removal.ts` 的共享检测器统一（分享过两次，等用户决定）。
6. **"点一下等一秒"没有复现**：Edge（WebGPU/WebGL2）与打包版都测不出；3.7.6–3.8.0 已经把回读批量化、
   spinner 延迟化，并去掉了屏幕选择里的深度回读。若再出现，最好在应用内加一个"上一次操作耗时"读数来定位。
7. 小尾巴：洞模式的像素信号（死胡同）、平面修复面板 / level-2 refine 的死代码、我们的 `H` / `Shift+H`
   是否等同上游 lock 语义（没核对过）。
8. **注意**：去掉 id 拾取之后，屏幕工具**没有"只选可见表面"这个选项了**（现在只有厚度近似）。
   如果用户想找回来，需要单独设计。
9. **三轴范围的百分比基准不一样**，是刻意的但值得记着：深度是"模型"的深度范围，左右/上下是"手势那个框"的
   范围。如果用户觉得混，可以统一成"手势框"（深度也按框内高斯的深度范围量）—— 那会改变现有手感。
