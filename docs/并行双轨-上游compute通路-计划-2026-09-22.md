## 0. 一句话立场

**并行可行，最终形态本来就该是"WebGPU 走上游通路、WebGL2 走现有通路"**（上游自己也是这么分流的）。
但**先花一次会话买"该不该做"的答案**（阶段 0 只读 spike），再决定要不要付接口重构的钱。

## 1. 两种"并行"，我们选 A

| | A. 双后端（选它）| B. 同后端两实现同时存在 |
| --- | --- | --- |
| 形态 | 按图形后端分流：WebGPU ⇒ 上游 compute 通路；WebGL2 ⇒ 现有引擎通路 | 同一后端里两套渲染器，运行时切换 |
| 代价 | 一份后端接口 + 两份实现（上游通路须补我们的功能）| 两个渲染器画同一批高斯（翻倍开销/状态互踩），且**每个新功能写两遍** |
| 回归 | 按后端分组跑（各 51 套件）| 51 × 2 后端 × 2 通路 = **204 次** |

⇒ 不做 B。用户界面不出现"两条路"，只有一个后端选择。

## 2. 功能重做清单（草案，阶段 0 里逐条核对）

我们挂在引擎 `GSplatInstance` + 自定义材质上的东西（换通路后各自何去何从）：

| 功能 | 现挂载点 | 判断 | 说明 |
| --- | --- | --- | --- |
| SH 波段切换 | `splat.ts` `rebuildMaterial` + 自定义着色器 `SH_BANDS` 定义 | **必须重写** | 上游 compute 投影自带 SH 求值，需接我们的 `view.bands` 语义并回归 |
| 逐通道曲线调色 / 色调 / 饱和 / 亮度 | `splat-shader.ts`(34 KB) + WGSL 双份 | **必须重写** | 上游有 `color-grade.ts`（可搬），但我们的**逐通道曲线 + 直方图 + 范围选区**是自研增量 |
| 直方图 / 范围选区 | `histogram.ts` / `range-slider.ts` / `select-by-range-shader.ts` | **部分可直接搬** | 上游 `data-processor/histogram-config.ts` 有直方图通路；我们的选区语义要保留 |
| 有向裁剪盒（box/cylinder/ellipsoid + 软边 + 预览）| 着色器内解析数学 | **必须重写** | 上游无等价物 |
| 选区高亮 / 描边 / underlay | **MRT RT0+RT1**（`camera.ts:767` splatTarget）| **必须重建 MRT 语义** | 上游合成管线自成一套，需重做 RT1 通路 |
| 拾取 / 画笔 / 套索 / 多边形 / 球刷 / 洪泛 / 吸管 | 引擎挑选 + 我们的 tools | **必须重接** | 上游 `picker.ts` 走 `renderSortedForPick` / `footprintIntersect`，可参考但要接我们的工具语义 |
| 测距 / 定向 / 地水面 | tools | **可保留**（不依赖渲染器）| 只吃拾取结果 |
| LOD | `editor-lod.ts` + `lod.ts` | **必须重写** | 上游 compute 有自身紧凑化，LOD 需重新设计 |
| 组渲染器（合并实体）/ 合并模式 / 对比模式 | `group-renderer`、`merge-scene.ts`、`compare-scene.ts` | **必须适配** | 这两套是**独立场景**，新通路要么支持、要么先禁用并明说 |
| PiP 相机预览（交换 sorter/orderTexture）| `camera-preview.ts`(1400+) | **必须重做** | 上游 PiP 走同一 `ProjectedSplatRenderer`，无第二份 centers/order |
| 交互期降级（分辨率缩放 + 我们的 blit）| `motion-quality.ts` + `blit-shader.ts` | **可保留**（与通路无关）| 上游另有"贡献剔除/遮挡剔除"可再叠 |
| 导出（图像/视频/旋转台/PLY/HTML）+ 排序等待 | `render.ts`(1500+)、`sortSplatsAndWait` | **必须重接** | 上游 capture 强制走排序路径（`lockedRenderMode`），思路可借 |
| 运动期随机透明 + resolve（已实现但休眠）| `motion-opaque.ts` + `blit-shader.ts` | **可删或保留** | 上游整条随机通路更完整（我们已判定观感不可接受）|
| AABB / 边界 / 网格 / 视图立方体 / 相机 | 引擎 + 自研 | **可保留** | 与渲染通路无关 |

> 上表的"必须重写"项 = 阶段 1 的工作量主体；**任何一条没做到功能平价之前，默认不能切换。**

## 3. 阶段 0：只读 spike（**建议现在只做这个**）

目标：用**你的真实模型**回答"值不值得"，而不是用任何代理指标。

* 分支：`feat/upstream-projected-spike`（从 `master` 开，独立、可整分支删除）。
* 内容：从 MIT 来源搬 `projected-splat-renderer.ts` + 它的着色器（compute 投影 / 紧凑化 /
  `ComputeRadixSort` / indirect draw / resolve），做成**只画不编辑**的最小可用：
  只读渲染 + 轨道/飞行相机 + 坐标拾取。**不接**选取、调色、裁剪、LOD、导出、PiP、合并/对比模式。
* 入口：独立开关（如 `?renderer=compute`）⇒ 主线行为与代码**完全不动**，出问题直接不传这个参数。
* 测量（三件事，缺一不可）：
  1. **帧率**：静止 / 慢转 / 快甩，与我们现通路在**同一模型、同一机位**下 AB 对比；
  2. **错序**：旋转时是否真的没有顺序错位（复用现有 `docs/probes/sort-lag.cjs` 的 `disp` 口径，量新通路）；
  3. **观感**：三张同机位截图（静止 / 运动中 / 停手）交给你肉眼判断 —— **这次不由我替你下结论**
     （前两轮我都在"用可计算代理替代肉眼"上栽了，规矩已写进文档）。
* **决策点**：三项都没有明确优势 ⇒ 砍掉，损失一次会话；有明确优势 ⇒ 进阶段 1。
* 验收口：主线 51 套件仍全绿（因为新通路只在带参数时启用）+ spike 分支自己的最小冒烟。

## 4. 阶段 1：抽后端接口（只有阶段 0 赢了才做）

* 目标形态：一个后端接口（`add / remove / replace / render / pick / bounds / sortStatus / export`），
  **现有通路先包一层**，行为逐像素不变（全套件 + 截图 diff 为证）；再把上游通路接进来。
* 默认仍是现通路。新功能在平价达成前**只实现一份**（现通路），避免双写税。
* 每步一个回滚 tag（照 `backup/pre-resolve-3.23.40` 的样子）。

## 5. 阶段 2：分流与切换

* WebGPU 默认切上游通路；WebGL2 保持现通路（= 天然双轨，也是上游的做法）。
* 老通路在"功能重做清单"全部平价前不删；打包维持单个 exe（两条路都在里面，按后端分流）。
* 回滚：`?renderer=engine` 强制回落 + tag 回退。

## 6. 风险与硬约束（提前摊开）

1. **WebGL2 不可能有等价物**（compute 只在 WebGPU）⇒ 永远存在两条通路 ⇒ 长期维护两份渲染实现。
2. **回归矩阵翻倍**：51 套件按后端分两列跑；新增渲染功能要考虑两边。
3. **上游也会换代**：搬过来的是 v3.3.0 快照，后续对不上游更新，等于接收了一份要自己养的渲染器。
4. **拾取/选取语义**是最容易出隐蔽 bug 的部分（上游用 GPU 紧凑列表求交，我们用引擎挑选）。
5. **合并/对比模式**（独立场景）要么一起适配，要么明确禁用 —— 不能默默坏掉。
