# 运动期"不依赖顺序"的渲染 —— **删除记录**（2026-09-23，用户判定）

> 一句话：运动期的两条替代画法（**随机透明** / **硬边裁剪**）及其全部配套代码已删除。
> 用户原话：**"不透明度和硬边裁剪对于视觉上的伤害太大了，我认为不必保留。"**
> 这是对 `dcf44a3`（运动帧不依赖顺序方向关闭）的最终定论：不是"默认关掉留着开关"，
> 而是**整条路删掉**。

## 1. 删掉了什么（清单，逐项可核对）

| 位置 | 内容 |
| --- | --- |
| `src/core/motion-opaque.ts` | 整个文件（`MotionOpaque` 类、`applyMotionOpaqueMaterial`、`registerMotionOpaqueEvents`、两个逃生开关、三种模式 off/stochastic/clip）|
| `src/shaders/splat-shader.ts` | `uMotionOpaque` / `uMotionAlphaClip` / `uMotionStochastic` 三个 uniform、`srStochasticThreshold()` 散列函数、片元里那段"按 alpha 取舍 + 写哨兵 alpha 2.0"的分支 |
| `src/shaders/splat-shader-wgsl.ts` | 同上（WGSL 侧逐字对应的一份）|
| `src/scene/scene.ts` | `motionOpaque` 实例、构造里的 `registerMotionOpaqueEvents`、`onPreRenderInner` 里每帧切材质的整段（含合并/组渲染那条）|
| `src/splat/splat.ts` | `setMotionOpaque()`、`_motionOpaque` 字段、`_sortAdmit()` 里"运动期停发排序"的早退 |
| `src/ui/settings-panel.ts` | 设置面板那一行（"运动期渲染"三档下拉）及其事件接线 |
| `static/locales/*.json` | 9 个语言各 4 个键（`panel.settings.motion-render{,.off,.stochastic,.clip}`），共 36 行 |
| `src/camera/camera.ts` | blit 的 resolve 开关：**恒为 0**（实现留在 `blit-shader.ts` 里备用，见 §3）|
| `docs/verify/verify-motion-opaque.cjs` | 旧回归套件（断言"这套机制工作正常"，机制没了必然失败）|
| `docs/probes/motion-opaque.cjs` | 旧取证探针 |

保留了一个**恒 false 的只读口** `splat.motionOpaque`：删掉它会变成 `undefined`，旧探针/套件读到的是
"未启用"还是"字段不存在"就分不清了 —— 静默失效比报错更难查。同时**没有**保留 `setMotionOpaque()`
（有入口就说明还能开）。

## 2. 新增的删除护栏：`docs/verify/verify-motion-render-removed.cjs`

删掉的东西最容易悄悄回来，所以把旧套件**反过来写**（`npm run verify:motion-removed`，9 项）：

1. `Scene` 上不再有 `motionOpaque` 实例
2. `Splat` 上不再有 `setMotionOpaque` 入口
3. `splat.motionOpaque` 恒 `false`
4. `motionRender.mode` 事件已注销（`invoke` 返回 `undefined`）
5. 材质上没有那三个 uniform
6. 运动帧确实是"相机在动"（否则后面几条是空话）
7. **运动帧的材质与停手帧完全一致**（旧实现会在运动帧切 `BLEND_NONE` + 深度写）
8. 停手后仍然一致
9. **运动期照常派发排序**（旧实现在运动期故意停发）

第 6~9 条是关键：前 5 条只证明"代码没了"，后 4 条证明"渲染行为真的回到了正常 alpha 混合"。

## 3. 删掉之后，能力上少了什么（**必须记住的代价**）

* **旋转时的排序错序问题回到原样**：以前这几条路是"运动帧干脆不依赖顺序"的结构性规避；
  现在运动帧照常 alpha 混合、照常排序，所以顺序滞后 ω·λ（20M 实测 λ≈155 ms）重新可见。
* 我们用过的**唯一**一条能在运动期消除错序的手段，就是它们；删掉等于**放弃这个方向**。
  剩下的可做方向（见 `docs/旋转错序-结构性规避与SuperSplat对照-2026-09-22.md` §7）是
  **只压缩滞后、不碰观感**的那种（延迟补偿/门限/排序频率），那部分代码**没动**。
* **一行相关代码都没删干净的检查**：`git grep -n "MotionOpaque\|motionOpaque\|uMotion"` 应只剩
  `splat.ts` 那个恒 false 的读口 + 文档里的历史记录。

### 为什么 blit 的 resolve 实现留着

`src/shaders/blit-shader.ts` 的 quad-resolve（把 1 spp 随机采样的噪声换成量化误差）**没有删**，
只是 `camera.ts` 把 `resolveMode` 恒置 0。理由：它是上游 SuperSplat 运动帧画法的必要配套，
而"引擎侧 WebGPU compute + 读回"是一个已立项的独立待办（见 `docs/待办-引擎WebGPU-compute.md`）——
那条路若哪天能通，运动帧同样会写哨兵 alpha，这道 resolve 可以**原样复用**。
留在那里的代价为零：`resolveMode = 0` 时它就是一次纯拷贝，与历史行为逐字节相同。
