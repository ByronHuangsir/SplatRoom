## 2. 这一轮最多的两类教训

### 2.1 按报告逐条修会漏 —— 要按**模式**扫全族

20 条里有三条属于"同族/同源漏网"：

* `StateOp` 家族有七个 op 在构造函数里数作用行，我第一批只修了**被点名的四个**
  （`SelectAll/None/Invert/HideSelection`），剩下 `UnhideAll` / `UndeleteSelection` / `Reset`
  是审查报告列全之后才补的（第 12 条）。
* `defaultLodIndex` 有**两份重复实现**（worker 不能 import 主线程 io 层），
  两份缺的是同一个空数组守卫，只改一份等于没改。
* `pickLod` 那条我只覆盖了"抛异常"路径，漏了"解析成 `undefined`"（第 16 条）。

### 2.2 只"标脏"不够，必须显式 flush

第 19 条（导出裁剪）第一版修法是"把直接改字节改成 `setBits`/`clearBits`"，
看起来干净，但护栏马上打回来：GPU 状态纹理只在 `Splat.updateState()`（flush + 计数）里上传，
而它由 `onPreRender` **按需**触发 ⇒ 少了显式 `flush()`，行为就退化成
"导出期间恰好有一帧才同步"的时好时坏 —— 这恰恰是原 bug 在真实路径上难复现的原因。
新护栏的第 4/5 条就是钉这一点（恢复逐字节还原 + 不留未刷新的脏区间）。
