## 2. 恢复过程（怎么来的，含核对数字）

1. `git clone .\交接包_20260920\SplatRoomV3-0-完整Git历史.bundle SplatRoomV3-0` → **179 个提交，HEAD = `c6a5ece`** ✓
2. 解压 `SplatRoomV3-0-源码与文档.zip` 并比对：**706 个文件逐字节 SHA256 全部一致**；其中 41 个是 git 忽略项（`dist\*.ply` 5 个夹具 + `scripts\dev-history\local\` 36 个复现脚本），已按交接包说明补进工作树 ✓
3. **行尾坑（新发现，交接包没写）**：本机 Git for Windows 的**系统级**配置是 `core.autocrlf=true`，而交接包里的工作树是**混合行尾**（460 个文件 CRLF＝当年 checkout 转出来的，205 个文件 LF＝当年被工具写入过的）。用默认配置克隆会让那 205 个文件变 CRLF → 与交接包快照不一致。
   **处理**：保持 `core.autocrlf=true`（与原机器一致），把 706 个文件按交接包逐字节覆盖回去 ⇒ **706/706 一致**，且 `git status` 干净。
   注意：**不要**在这个仓库上跑 `git checkout -- .` / `git reset --hard`，那会把那 205 个文件改回 CRLF（内容不变，但就不是交接包快照了）。

## 6. 夹具现状：真实模型不在本机，已补一个**合成**大模型

两个真实扫描件（13,007,105 点的 `merged-scene.ply`、20,000,000 点的 `splat_273200.ply`）**没有随交接包过来**（交接包第 1 条提醒），本机原来最大的夹具只有 7.8 MB。为此新增：

- **生成器**：`docs/verify/gen-synth-large-splat.cjs`（新文件，按仓库既有生成器约定写：binary_little_endian / 同列序 / 同编码）
- **形状**：55% 密集核心（半径 ~150）＋ 43% 房间尺度 ＋ 2% 远噪声壳层（半径 ~4800）⇒ **AABB 半对角线 8305 = 核心半径的 ×55**，与真实扫描件"被噪声撑到 ×54"一致（③④ 两个问题都依赖这个形状）
- **实测**：`--points=20000000 --sh=3` 生成**耗时 9.6 秒**，文件 **4,720,001,579 B（4.72 GB）**，59 列 / 236 B 每点，头部声明尺寸与文件尺寸**精确相等**（splat-transform 会校验，差一个字节就报 corrupt）
- **装载实测**（硬链接成 `dist\test-20m.ply`，WebGPU）：**20,000,000 splats / shBands=3 / AABB 半对角线 8305 / 无报错**，导入 **72.8 秒**（18 个 256 MB Range 分块）—— 与交接包记的真实 20M"导入 ~90 秒"同一量级
- 小样本通路核对：`--points=200000 --sh=3` → 装载 **200,000 splats / shBands=3**，1.1 秒

```powershell
# 生成（放仓库外，避免打包时 >4.2 GB 文件进 dist 把 electron-builder 打爆）
node docs\verify\gen-synth-large-splat.cjs --points=20000000 --sh=3 --out="C:\Users\admin\Desktop\3DGS\DeepSeek\SplatRoomV3\_tmp\synth-20m-sh3.ply"
# 用时硬链接进 dist（不占额外空间），跑完立刻删
New-Item -ItemType HardLink -Path dist\test-20m.ply -Target "C:\Users\admin\Desktop\3DGS\DeepSeek\SplatRoomV3\_tmp\synth-20m-sh3.ply"
Remove-Item dist\test-20m.ply -Force
```

**诚实边界**：这是**合成**夹具，不是用户的真实扫描件。它复现的是"点数量级 + 密集核心 + 被噪声撑爆的 AABB"这三件与性能/取景有关的事，**不能**替代真实扫描件上"某个具体文物好不好看、记得像不像"的验收；凡是在它上面量到的结论，汇报时都要写明"合成 20M"。
