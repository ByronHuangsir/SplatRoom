# 曲线调色（Curves）：引擎侧实现 + 面板设计（2026-09-22）

用户休息前给的第 3 件事是"探索一下调色面板增加曲线调色"。这一轮做到的是
**引擎侧完整落地**（模型 → 着色器 → CPU 导出镜像 → 材质接线），**面板 UI 还没做**。
本文写清"已经能用的部分怎么用、验证到什么程度、UI 那一层要动哪些文件、坑在哪"。

---

## 1. 已经做完的（可以立刻验证）

### 1.1 模型与采样（`src/core/color-curves.ts`，纯函数）

- `CURVE_SAMPLES = 33`（0 与 1 都是采样点，32 段，每段 1/32）；
- `sampleCurve(points)`：控制点 → 33 点采样表，**单调保形三次插值（Fritsch–Carlson）**。
  为什么不用 Catmull-Rom：普通三次样条会过冲（暗部出现负值、亮部冲出去），
  摄影曲线的手感是"拉中间点不把两端甩出去"，单调插值保证不产生新的极值。
- `isIdentityCurve` / `identityCurveSamples` / `evaluateCurveAt`（CPU 求值，与着色器同一套线性插值）/
  `applyCurveToRGB`。
- 边界行为：控制点夹到 `[0,1]`、重复 x 取最后一个、NaN 原样透传、±∞ 夹到两端。

### 1.2 着色器（GLSL 与 WGSL 各一份，插在顶点分级之后）

```
color = color * clrScale + vec4(clrOffset, 0.0);      // 原有：白场/黑场/亮度/色温
if (uCurveEnabled > 0.5) { color = applyCurve(color); } // 新增：33 点 LUT 线性插值
```

- 曲线表是一张 **33×1 R32F 纹理**（`Splat.curveTexture`），
  GLSL 用 `texelFetch(uCurve, ivec2(i,0), 0).r`、WGSL 用 `textureLoad(uCurve, vec2i(i,0), 0).r`；
- 插在**顶点阶段**（`splat-shader.ts:305` 之后 / `splat-shader-wgsl.ts:333` 之后）：
  这个 fork 的顶点 chunk 本来就有纹理先例（`splatState` / `splatTransform` / `transformPalette`），
  片元 chunk 目前**一个 sampler 都没有**，第一次往片元里塞纹理的风险更大；
- **默认零改动**：`uCurveEnabled = 0` 时整段跳过，且 `setCurve(null)` 与"设了一条恒等曲线"
  等价（`isIdentityCurve` 短路）⇒ 不设曲线时画面与"没有这个功能"**逐像素一致**（实测最大差 0）。

### 1.3 材质接线（`src/splat/splat.ts`）

- `Splat.setCurve(samples: Float32Array | null)`：写纹理（`lock/unlock`）+ 发 `splat.curve` 事件；
- `Splat.curve` getter：给导出镜像读；
- `onPreRender` 里按 `_colorGradeEnabled` 推 `uCurveEnabled`（调色整体关掉时曲线也一起关）；
- 曲线纹理在 `rebuildMaterial` 里绑定一次。

### 1.4 CPU 导出镜像（`src/core/color-grade.ts`）

`ColorGrade` 的 `apply()` 在 scale/offset 之后、饱和度之前施加同一条曲线（`evaluateCurveAt`），
并且**把曲线算进 `hasTint`** —— 这一条很关键：不算进去的话
`splat-serialize.ts` 的 `if (!keepColorTint && (grade.hasTint || grade.hasHsl))` 会跳过烘焙，
导出图与视口不一致。

### 1.5 验证

- `docs/verify/verify-color-curves.mts`（**11 项**，纯 node）：恒等、端点固定、单调不过冲、
  抬亮/压暗中点方向、恒定曲线（抬黑）、越界与重复 x、**`evaluateCurveAt` 与独立重写的着色器查找
  逐位一致（最大差 0.00e+0）**、NaN/∞ 行为、恒等表是 no-op、逐通道施加。
- `docs/verify/verify-color-curve.cjs`（**8 项**，真浏览器，双后端 0 失败）：
  开关默认 0 / 恒等曲线等价于不设 / 恒等画面逐像素一致（0/3,927,040 个通道有变化）/
  抬亮曲线 meanLum 0.4197 → 0.6234（+0.2037）且开关变 1 / 压暗曲线 → 0.2801（−0.1396）/
  S 曲线改变分布形状（展布 0.0333 → 0.0350，低端相对中位数被压 0.0294 → 0.0328）/
  清空后逐像素回到基线 / 无 pageerror。

**怎么手动试**：打开应用、导入任意模型，在控制台执行

```js
const s = window.scene.getElementsByType('splat').slice(-1)[0];
const table = new Float32Array(33);
for (let i = 0; i < 33; i++) { const x = i / 32; table[i] = Math.min(1, Math.max(0, x + 0.35 * x * (1 - x) * (2 * x - 1))); }
s.setCurve(table);   // S 曲线（拉对比）
s.setCurve(null);    // 还原
```

## 2. 还没做的：面板 UI 与持久化

下面这些是**设计稿级别**的清单（已按探查结果核对过位置），实现顺序建议从上到下：

| # | 文件 | 要做什么 |
|---|---|---|
| 1 | `src/ui/color-panel.ts` | 新增"曲线"分类：一个 SVG 方块 + 4 个通道页签（RGB 主曲线 / 红 / 绿 / 蓝），拖动控制点 → `sampleCurve()` → `splat.setCurve()`；复用现有 `start()` / `end()` 手势包裹以进 undo |
| 2 | `src/ui/scss/color-panel.scss` | 曲线编辑器样式（网格、对角线、控制点、通道页签），可直接借鉴现有 `.hsl-tab-bar` / `.hsl-tab-content` |
| 3 | `src/core/edit-ops.ts` | `ColorAdjustment` 加 `curve?: Float32Array \| null`，`SetSplatColorAdjustmentOp` 的 `do()`/`undo()` 各一行 |
| 4 | `src/splat/splat.ts` | `docSerialize()` / `docDeserialize()` 带上曲线（**可选 + 默认 null**，旧 `.ssproj` 不能崩） |
| 5 | `src/app/color-grade-file.ts` | `.sscg` 加字段 + `SSCG_VERSION` 4 → 5（`deserializeGrade` 已是向后兼容写法） |
| 6 | `src/ui/data-panel.ts` | `colorEvents` 列表加 `splat.curve`（**注意：`hslHue/Sat/Lum` 今天就漏在里面**，顺手补上） |
| 7 | 9 个语言文件 | 曲线相关文案（`panel.colors.curve-*`），各语言键数必须一致（现为 690） |

### 每题一个坑（探查得到，别踩）

1. **`hasTint` 是 `readonly` 且构造时冻结** —— 曲线必须并进去，否则 `.ply/.sog` 导出会跳过烘焙。
   （本轮已经改好。）
2. **着色器里只能插一次**：片元的调用序列是 `highlights → shadows → contrast → HSL`,
   顶点是 `clrScale/offset → （新的）曲线`。两条链路的**顺序**要和 CPU 镜像完全一致，
   否则导出与视口会不一致 —— 本轮把曲线放在 CPU 的 scale/offset 之后，与顶点侧对齐。
3. **直方图 / 范围选择目前只镜像了 scale/offset/saturation**（`src/shaders/splat-value-shader.ts:112-116`），
   曲线要在那两条通路生效，需要`calc-histogram.ts` / `select-by-range.ts` 各绑一份曲线（推荐用
   uniform 数组而不是纹理：那两条通路本来就是散装 uniform，且是 `resolve(scope, values)` 直喂值）。
4. **分组渲染恒为中性**（`src/splat/group-renderer.ts:611-624`）：曲线也要在中性分支里写 0/恒等。
5. **`.ssproj` 没有 schema 校验**（只有 `version: 1`），新字段必须按"可选 + 默认"读。

### 为什么先做引擎再做 UI（而不是反过来）

四份数学（GLSL 顶点/片元 × WGSL、CPU、值通路）里最容易出错的是**采样与插值**，
而它现在只有一份实现且被 22 项断言钉住（11 项纯函数 + 8 项像素 + 3 项在 tone-range 套件里顺带）。
UI 只是"控制点 → 33 点表"的编辑器，接上去之后回归面很小。
