## 结论：SuperSplat V3 已开源，实现可精确对齐

- 仓库 `playcanvas/supersplat`，**MIT**，最新 **v3.1.2**（2026-09-11），10k stars，仍活跃。
- **纯 WebGPU**：`createGraphicsDevice(..., { deviceTypes: ['webgpu'] })`，全部 shader 为 WGSL，判交是 compute（`src/data-processor/intersect.ts` 单 compute 五模式 + `src/shaders/footprint-intersect-shader.ts`）。
- 因此代码**不能直接搬**到 SplatRoom（WebGL2 全屏 fragment），但**算法与语义可 1:1 移植**——3.2.0 已完成。

## 上游真实语义（源码核对）

```js
// supersplat/src/editor.ts
const selectionMethod = () => useDepth ? 'pick'
    : footprint > 0 ? 'footprint' : 'centers';
```

| depth | footprint | 屏幕空间手势（rect / 刷子 / 套索 / 多边形 / 单击）|
|---|---|---|
| off | 0 | `centers`：穿透式中心判交 |
| off | >0 | `footprint`：投影椭圆 vs 区域，**穿透所有层** |
| on | 0 | `pick` ∩ `centers`（区域内可见 ∩ 中心在区域）|
| on | >0 | `pick`：区域内可见覆盖 |

- 开关是 `selection.useDepth`(bool, 默认 false) + `selection.footprint`(**数字 0/1**, 默认 0)。
- `footprint` 以标量进入 sphere/box/球刷：0=中心点，>0=按 **2√2σ 渲染椭球**做**支撑函数**判定；**depth 不影响体积工具**（上游只传 footprint）。
- 球刷 = **一条世界路径**：`intersectMany` 一次批量深度拾取 → 每点带半径（`半径px × worldSizePerPixel(depth)`）→ **负半径 = 深度断裂开新子路径** → **整条笔画 1 次 dispatch、1 个历史 op**；footprint=0 时用屏幕笔画 mask 门控（中心须投影在笔画内）。
- 上游 `Shift+B` = 球刷，`N` = depth，`M` = footprint（M 同时是 centers↔rings 视图档切换）。

## SplatRoom V3 落地（3.2.0）

**四象限与上游一致**（`src/editor.ts` 的 `screenSelectionMethod`）：

- `centers` / `footprint` 走 GPU 判交 `src/data-processor/intersect.ts`（GLSL 移植）：
  - 新增 `footprint` uniform；屏幕空间模式用**投影椭圆 vs 区域**（mask 模式采样椭圆中心 + 三轴 ±0.5/±1.0；rect 模式另加"矩形角点在椭圆内"的二次型判定，覆盖大椭圆套小矩形）；
  - 体积模式用**支撑函数**（`splatBasis` + 最近点分离 vs 方向跨度），从 `transformA.w` / `transformB` 还原四元数与尺度，经 transform palette 进入世界 / 形状空间。
- `pick` 象限：`pickRectIds` / `pickMaskIds` 得到区域内可见集合；`footprint=0` 时与中心判交取**交集**（`retainVisibleIds`），否则直接用可见集合。
- **删除 3.1.3 的 surface-map 比较方案**（`surfaceOnly`/`surfaceMap` uniform、`camera.renderSurfaceMap`）：上游机制更简单，且没有跨帧共享 work target 的时序风险。3.1.3 附带的"体积工具吃 depth"语义一并移除（上游体积工具不吃 depth）。
- 球刷重构为**路径一次 dispatch**：`camera.intersectMany`（每 splat 一次深度 pass + `picker.readDepths` 分块批量回读 + 相机姿态快照）+ GLSL 模式 4（路径点球体 + 相邻点**胶囊** + `pathMin`/`pathMax` AABB 裁剪 + footprint 支撑加宽 + `footprint=0` 时笔画 mask 门控）。路径点以 **RGBA32F 纹理**上传（`lock()/unlock()`，NEAREST，grow-only）。
- `camera.worldSizePerPixel(depth)` 由投影矩阵推导（含正交），替代原先手写 `tan(fov/2)`。
- 开关状态抽到 `src/selection-flags.ts`，**在 UI 构建前注册**（settings 面板构造时会读这两个值，否则会报 `function not found`）。
- 快捷键：`N` = depth、`Shift+M` = footprint（M 在本仓库已是 centers/rings 视图切换，故用 shift）、`Shift+B` = 球刷（与上游一致）。
- 设置面板两行开关默认关 / 0（保持历史中心判定行为），localStorage 持久化（兼容 3.1.3 旧键名）。

## 无头真机验证（已跑通）

`docs/verify/verify-selection-depth.cjs`（puppeteer-core + Edge swiftshader）+ `docs/verify/gen-test-splat.cjs`（1200 前墙 + 800 后墙 = 2000 高斯）：

| 用例 | 选中数 | 期望 |
|---|---|---|
| rect / centers | 409 | 基线 |
| rect / footprint | 542 | ⊃ centers（覆盖加宽）|
| rect / depth | 194 | ⊂ centers（仅表面）|
| rect / depth+footprint | 242 | 可见覆盖，介于两者之间 |
| mask / footprint | 183 | > mask / depth |
| mask / depth | 78 | 仅可见 |
| sphere(0.4) / centers | 169 | 基线 |
| sphere(0.4) / footprint | 210 | ⊃ centers（支撑函数加宽）|
| 球刷路径（footprint 0） | 11 | 批量拾取 + 胶囊 |
| 球刷路径（footprint 1） | 44 | 覆盖加宽 |

结果 **errors / warnings 均为空**（无 GLSL 编译错误、无运行时报错）。该验证链在过程中抓到并修掉了一个真实 GLSL 编译错误（`clipPoint` 的 out 参数维数不匹配），也暴露了开关事件注册顺序问题。

> 注：测试模型每次生成都是随机分布，因此各轮的具体数字会有小幅浮动；固化的判据是**序关系**（footprint ⊃ centers、depth ⊂ centers、depth+footprint 介于两者之间）。

复现：`node docs/verify/gen-test-splat.cjs dist/test-model.ply` → `npx serve dist -C -l 3100` → `node docs/verify/verify-selection-depth.cjs http://localhost:3100/`（记得跑完删掉 `dist/test-model.ply`，否则会打进包里）。

## 已知边界

- mask 模式的 footprint 用**椭圆上有限采样**近似（中心 + 三轴 ±0.5/±1.0，共 7 点），不是逐行区间精算：极细笔画切过极大高斯边缘时可能漏选；rect 模式是解析判定，无此近似。
- WebGPU 渲染后端（V3 实验开关）下未验证：这些路径依赖 WebGL2 fragment 判交与 RGBA32F 纹理上传。
- 上游 footprint 开关会切换 centers/rings 视图档；SplatRoom 保持**显示与选择解耦**（保留超集能力，未跟随该耦合）。
- 球刷仍是"松手后一次成选"（一次 op），上游是笔画过程中实时累积；换来的是确定性的单次历史记录。
