# 视野角快捷面板：位置与版式（2026-09-22，四轮，v3.23.37）

这块面板（视野角 / 显示边界 / 显示网格）是用户要求"这三个功能很常用"加出来的，位置、版式、事件处理改了四轮。
放在一起写，因为**每一轮的结论都在推翻上一轮的约束**。

## 第一轮（v3.23.33）：坐到右上角坐标轴正下方

* 位置 `right: 12px; top: 146px`（坐标轴 140px 高 + 6px 间隙），尺寸 `204 × 96`，3 行。
* 版式：视野角（单行，滑轨跟在标签后面、藏掉 PCUI 数字输入框）、显示边界、显示网格。
* 设置面板里原有的三份**保持不动**（同一套事件的第二个入口，两边永远同步）。

## 第二轮（v3.23.34 / 3.23.35）：两个遮挡 bug

1. **压住右侧工具栏最上面两个按钮** ⇒ 工具栏从"垂直居中"改成固定 `top: 254px`。
2. **调色面板打开后被这块压住**（实测快捷面板 `[1046,146,1268,242]` vs 调色面板 `[858,24,1178,744]`，
   重叠 132×96px）。先做"让位到面板列左边"（`right: 434px`，确实不重叠了），但那就不在坐标轴下方了；
   把两个方案摆给用户后**用户选了"面板打开时隐藏"**（`:has()` 规则）。

## 第三轮（v3.23.36）：两行 + 左上角菜单栏右侧（用户提的优化）

用户原话：① 分成两行，视野角一行、显示一行（显示后面跟边界/开关和网格/开关）；② 面板放到左上角菜单栏右侧。

* 版式 3 行 → 2 行：`[视野角 75°][滑轨]` / `[显示][边界◯][网格◯]`；面板 `204×96 → 254×68`，滑轨 `121px → 153px`。
* 新增 3 个文案键（`panel.settings.show` / `short-bounding-box` / `short-grid`），**9 个语言包手写补齐**：
  各语言"显示"位置不同（德语是后缀 `Raster anzeigen`、日语没这个词），不能靠裁前缀生成。
* 位置：实测菜单栏 `[24,24,444,74]`，面板 `[456,20,710,88]`（间距 12px）。`left` **由 JS 量** `#menu-bar`
  右边缘 + `ResizeObserver` 跟随（菜单栏宽度随语言/折叠变化），SCSS 的 `456px` 只是首帧兜底。
* **坑**：`ResizeObserver` 一开始写在构造函数里，那时 `#menu-bar` 还没进 DOM ⇒ `bar` 是 `null`，观察器没挂上，
  面板菜单栏变宽也不跟。是回归里"菜单栏变宽后必须跟着走"那条断言抓出来的（加了 3 个字符 × 6 项，
  菜单栏 444 → 648，面板纹丝不动 ⇒ FAIL 间距 −192px）。改成 rAF 之后测量 + 惰性挂载后：648 → 面板 660 ✓。
* 顺手删掉 `:has()` 隐藏规则：面板到左上角后与右侧面板 x 区间不相交 ⇒ 第二轮"挪位 vs 隐藏"的两难自动消失。

## 第四轮（v3.23.37）：开关点不动 + 第二行对齐撑满

### ① 开关点了没反应 —— 真凶是**指针捕获**，不是 z-index / pointer-events

用户报"开关无法操作，点击没反应"。逐层排查（`_tmp\diag-vqc-click.cjs` / `diag-vqc-events2.cjs`）：

* `elementFromPoint` 在开关中心命中的**就是开关本身** ⇒ 没有被任何东西盖住，也不是 `pointer-events` 问题。
* 但真鼠标点击后开关值不变；事件追踪显示：
  **`pointerdown` / `mousedown` 的 target 是开关，而 `pointerup` / `mouseup` / `click` 的 target 变成了 `#canvas-container`**。
* 根因：面板挂在 `#canvas-container` 里，而**相机控制器**在 `#canvas-container` 上监听 `pointerdown` 并
  `target.setPointerCapture(event.pointerId)`（`src/camera/controllers.ts:132`，`target` = `#canvas-container`）。
  pointerdown 一冒泡上去，指针捕获就被相机抢走 ⇒ 后续 pointerup/mouseup/**click 全部改派到 `#canvas-container`**；
  而 PCUI 的 `BooleanInput` 只在 `_onClick` 里翻转（`node_modules/@playcanvas/pcui/.../BooleanInput/index.mjs:61`）
  ⇒ 永远收不到 click，开关当然点不动。副作用还有：在面板上按下会被当成相机拖动。
* 修法：和 `scene-panel` / `settings-panel` / `color-panel` 等面板一样，拦下指针事件：

```ts
['pointerdown', 'pointerup', 'pointermove', 'wheel', 'dblclick'].forEach((eventName) => {
    this.dom.addEventListener(eventName, (event: Event) => event.stopPropagation());
});
```

* **这个 bug 从 v3.23.33 第一版就在**（右上角时同样存在），一直没被发现，是因为回归里用的是
  `dispatchEvent(new PointerEvent(...))` **合成事件**——直接在元素上派发会绕过指针捕获，测不出真鼠标的改派。
  这一轮把回归改成 `page.mouse` 真点击/真拖拽，并加了一条 `camera.userDragging === false`
  （点完面板不应把指针交给相机控制器）的断言，避免同类问题再溜过去。

### ② 版式：`显示` 与 `视野角` 左对齐，`边界` / `网格` 往右推开撑满整行

`.vqc-display-row { justify-content: space-between; }` —— 三块分别贴左、居中、贴右。

实测：标签左边缘 `[471, 471, 526, 627]`（「视野角…」与「显示」都是 471，对齐）；
第一行右端 = 第二行最右 = **701**（撑满）。注意**不能拿滑轨右端（695）比**：滑轨自身还有 6px 内边距。

### ③ 回归脚本自己的两个坑（记下来免得再犯）

* 拖滑轨要用 `page.mouse`，而且**每次拖动前必须重新量滑轨坐标**：角度读数并进标签文本里，标签宽度随位数变化
  （`视野角 75°` → `视野角 117°`），滑轨的 left 会跟着挪几个像素；用旧坐标会按到标签上 ⇒
  PCUI 收不到 pointerdown，值不动（第一版"第二次拖拽不生效"就是这么来的，一度被误判成 app 的 bug）。
* 别把"像素 → 角度"的映射写死在断言里（滑轨内部有 padding，拖到 95° 位置实测落到 98.4）；
  改成分两段真拖：最右 ≈ 上限、最左 ≈ 下限，断言 `fovHigh - fovLow > 60`。实测 75 → 116.7 → 17.4。
