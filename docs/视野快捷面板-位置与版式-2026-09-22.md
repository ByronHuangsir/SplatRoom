# 视野角快捷面板：位置与版式（2026-09-22，三轮，v3.23.36）

这块面板（视野角 / 显示边界 / 显示网格）是用户要求"这三个功能很常用"加出来的，位置和版式改了三轮。
本文把三轮放在一起，因为**每一轮的结论都在推翻上一轮的约束**——第三轮换位置之后，前两轮为了避让而加的东西全部可以删掉。

## 第一轮（v3.23.33）：坐到右上角坐标轴正下方

* 位置：`right: 12px; top: 146px`（坐标轴 140px 高 + 6px 间隙），尺寸 `204 × 96`，3 行。
* 版式：视野角（单行，滑轨跟在标签后面、藏掉 PCUI 数字输入框）、显示边界、显示网格。
* 设置面板里原有的三份**保持不动**（同一套事件的第二个入口，两边永远同步）。

## 第二轮（v3.23.34 / 3.23.35）：两个遮挡 bug

1. **压住右侧工具栏最上面两个按钮** ⇒ 把工具栏从"垂直居中"改成固定 `top: 254px`。
2. **调色面板打开后被这块压住**（实测快捷面板 `[1046,146,1268,242]` vs 调色面板 `[858,24,1178,744]`，
   重叠 132×96px）。先做了"让位到面板列左边"（`right: 434px`，实测确实不重叠），
   但那样它就不在坐标轴下方了——把两个方案摆给用户后，**用户选了"面板打开时隐藏"**：

```scss
#canvas-container:has(#color-panel:not(.pcui-hidden)) #view-quick-controls,
#canvas-container:has(#settings-panel:not(.pcui-hidden)) #view-quick-controls { display: none; }
```

## 第三轮（v3.23.36，用户提的优化）：两行 + 左上角菜单栏右侧

用户原话：① 分成两行，视野角一行、显示一行（显示后面跟边界/开关和网格/开关）；② 面板放到左上角菜单栏右侧。

### 版式：3 行 → 2 行

```
第一行  [视野角 75°] [————————————滑轨————————————]
第二行  [显示] [边界 ◯] [网格 ◯]
```

* 原来是 3 行（一行一个开关），现在两个开关共用一次「显示」前缀压成一行。
* 实测：面板 `204 × 96` → **`254 × 68`**（矮了 28px）；视野角滑轨 **121px → 153px**（面板变宽，轨道跟着变长）。
* 新增 3 个文案键 `panel.settings.show` / `panel.settings.short-bounding-box` / `panel.settings.short-grid`，
  **9 个语言包全部补齐**（zh-CN 显示/边界/网格、en Show/Bounds/Grid、de Anzeigen/Begrenzung/Raster、
  es Mostrar/Límites/Cuadrícula、fr Afficher/Limites/Grille、ja 表示/境界/グリッド、ko 표시/경계/그리드、
  pt-BR Mostrar/Limite/Grade、ru Показать/Границы/Сетка）。
  为什么不靠"把 `显示边界` 裁掉前缀"生成短标签：各语言的"显示"位置不同——德语是后缀（`Raster anzeigen`）、
  日语压根没这个词（`グリッド`），自动裁前缀不可靠，所以逐语言手写。

### 位置：左上角、菜单栏右侧（`left` 必须测量，不能写死）

* 实测菜单栏 `#menu-bar` = `[24, 24, 444, 74]`（中文 6 个菜单项 + 折叠箭头），
  面板实测落在 **`[456, 20, 710, 88]`** ⇒ 水平间距 12px、顶边 20px（与菜单栏视觉对齐）。
* 不压菜单栏（444 < 456）、不压左上角场景管理器 `[24, 102, 344, 530]`。
* **`left` 由 JS 量 `#menu-bar` 的右边缘后写入**：菜单栏宽度随语言（德语/日语更长）和折叠状态变化，
  写死 456 一定会错位。用 `ResizeObserver` 跟着菜单栏走；SCSS 里的 `456px` 只是首帧兜底。
* ⚠️ **踩到的坑**：`ResizeObserver` / `document.querySelector('#menu-bar')` 一开始写在构造函数里，
  那时菜单栏**还没进 DOM** ⇒ `bar` 是 `null`，观察器没挂上，面板只会停在首帧位置、菜单栏变宽也不跟。
  是回归里新加的"菜单栏变宽后必须跟着走"这条断言抓出来的（把 6 个菜单项文字各加长 3 个字符，
  菜单栏 444 → 648，面板却纹丝不动 ⇒ FAIL）。改成 rAF 之后再测量、并在里面惰性挂观察器后，
  实测 648 → 面板 `[660, 20, 914, 88]`（间距 12px），文字还原后回到 456。

### 顺手删掉的东西

* `:has()` 隐藏规则：**删了**。面板到了左上角，右侧面板（`right: 102`，x 858→1178）与它 x 区间完全不相交，
  实测两个面板打开时快捷面板仍可见且不重叠 ⇒ 既不用隐藏也不用挪位。第二轮那个两难（挪位 vs 隐藏）**自动消失**。
* 右侧工具栏**保持**第二轮下移后的 `top: 254px`：它现在的空档与这块面板无关，不动比动安全（要恢复垂直居中说一声）。
