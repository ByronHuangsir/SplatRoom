## 逐条结论

### ①表示/隐藏 Splats 后，已删除的点全部又出现了 —— 已定位，已修
- 右侧工具栏那个按钮的事件是 `camera.toggleOverlay`（`src/ui/right-toolbar.ts:164`），它切的是
  **点覆盖层 `SplatOverlay`**（`enabled` 要求 `camera.mode === 'centers'`，而
  `src/core/preferences.ts:97` 的默认值就是 `centers`，所以这个按钮人人都会碰到）。
- `src/splat/splat-overlay.ts` 在 **WebGPU** 上是"恒等序纹理 + 画 `splat.numSplats` 个"，
  而 `splat.numSplats` = 行数 − 已删除数；着色器里只判了锁定位（bit 2），注释写着
  "deleted splats are already excluded from order texture" —— 那只在 WebGL2 成立
  （引擎的 order texture 是排序后的可见集合）。**于是 WebGPU 下前 N 行照画，删除位无人过问。**
- 修法：`src/shaders/splat-overlay-shader.ts` 自己判 bit 4（`overlayShowDeleted` 可放开），
  `src/splat/splat-overlay.ts` 在 WebGPU 下改成画**全部行**（`splat.splatData.numSplats`）并每帧
  下发 `overlayShowDeleted`。
- 验证：`window.__SPLATROOM_VIEWER_STREAM__` 无关；用 20M 模型 → 删一批点 → 切 overlay →
  数"屏幕内点数"应与"未删除点数"一致（原实现会多画）。

### ②底部"高斯点数据"展开没有任何数据 —— 已定位，已修（子代理在改）
- 控制台每次都有：`CommandQueue task failed TypeError: e.updateBegin is not a function`。
- 根因：`src/data-processor/calc-histogram.ts:241-257` 的 `clearRT()` 与
  `src/data-processor/draw-points.ts:32-70` 的 `drawPointsWithShader()` 用了 **WebGL 专用**
  `updateBegin()/updateEnd()`（`WebgpuGraphicsDevice` 没有这两个方法），
  且 `src/shaders/histogram-shaders.ts:101` 的 bin 顶点着色器赋值 `gl_PointSize`
  （WebGPU 转 WGSL 会丢入口点 → 非法 pipeline）。
- 直方图 pass1/pass2 用的是 `drawQuadWithShader`（后端无关）所以没事，只有 pass3（bin 累加）炸。
- 结果：直方图每次 `run()` 都抛异常 → 面板里"计数/选中数"与直方图**全空**（属性名列表还在，
  所以用户看到的是"展开了但没有任何数据"）。

### ③选择范围只能收缩、无法扩展 —— 尚未复现，待查（有强假设）
- 用公开事件做的合成复现**是能扩展的**：先 40–60% 矩形 → 选中 19,997,733；再用更大矩形 `add`
  → 19,999,986（`expanded: true`）。所以问题不在 `select.rect` 这条路。
- 强假设（待验证）：**深度/左右滑块的范围是按 AABB 沿视轴算的**，而 AABB 被 18 km 噪声点撑爆，
  真正要看的 153 单位密集区只占滑块行程的 **0.85%**，A3 把深度量化成 Uint16 后密集区只占几百格
  —— 于是"拉滑块几乎没反应 / 只能收缩"。另外控制台有
  `<g> attribute transform: Expected number, "translate(NaN, NaN)"`（出自
  `src/ui/bound-dimensions-overlay.ts:180` 那种 `toFixed(1)` 拼 NaN 的写法），说明某些量算成了 NaN。
- 下一步：驱动真实滑块（`selection.depthRange` / 深度条 DOM）在 20M 上复现，并检查
  `poseExtent()` / `rangeDistances()` 用的是不是原始 min/max。

### ④"框显所选"只显示一小块 —— 已定位，已修
实测四种状态（20M）：

| 状态 | 相机到密集中心 | 密集半径 | 比值 | 屏内点数 |
|---|---|---|---|---|
| 导入后 | 16115 | 153.2 | ×105 | 100% |
| 框显所选（无选中） | 8297 | 153.2 | ×54 | 100% |
| 重置相机 | 13629 | 153.2 | ×89 | 100% |
| 框显所选（全选中） | 8297 | 153.2 | ×54 | 100% |

- 根因：`Splat.focalPoint()` 是对的（密集中心），但**半径用的是
  `worldBound.halfExtents.length()` = AABB 半对角线**（本夹具 8297~16115），被远处噪声点撑爆
  （`src/camera/camera.ts` 的 `getSplatInfo`、`src/app/editor.ts` 的 `camera.focus` 处理器）。
  相机因此落在 8~16 km 外，屏幕上只剩一个点。
- 修法：新增 `Splat.framingRadius()` = **裁剪包围盒**半对角线（按轴取 1%~99% 分位、抽样 ≤20 万点、
  ×1.1 余量），三处取景都用它。实测 20M：取景半径 **301.7**（AABB 8297.4），框显所选后
  相机到密集中心 301.67（修复前 8297）、比值 1.0。
  为什么不用 `denseRadius()`（不透明度×尺度的加权 3σ）：它会把薄墙/稀疏结构也裁掉，
  实测直接让 `verify-mask-vs-rect` / `verify-equirect-export` 两套回归的取景前提失效；
  裁剪分位数只丢极值、不加权，正常模型上与 AABB 同量级（这两套回归改用裁剪包围盒后恢复 failed=0）。

### ⑤"重置相机"要回到密集区斜上方 15° —— 已定位，已修
- 原实现：`setFocalPoint(0,0,0)` + `setAzimElev(0,0)` + `setDistance(initialZoom)`
  → 实测相机停在离模型 13629 处（模型密集区 153），什么也看不到。
- 修法（`src/app/editor.ts` 的 `camera.reset` 分支）：密集中心 + `framingRadius()` +
  `setAzimElev(0, -15)`（`calcForwardVec` 的 `y = sin(-elev) > 0` ⇒ 相机在上方 15°、俯视）。
  没有模型时保持原来的默认视角。

### ⑥2000 万点不如浏览器版 SuperSplat 3.3.0 流畅 —— 已量到热点，方案调研中
- 已量到的本机热点（20M）：
  - `select.rect` 一次 **1275ms**（用户框选时的主要卡顿来源）
  - `updateState(deleted)` 179ms（重建 20M 的排序映射）
  - `Splat.focalPoint()` 是**整点遍历 + 每点 2 次 `Math.exp`**（20M ⇒ 4000 万次 exp，秒级），
    每次"框显所选"都跑一遍；而同一个文件里的 `denseRadius()` 对 >50 万点**会抽样**
    —— `focalPoint()` 应该同样抽样（或缓存）。
  - 轨道旋转时 max 462.8ms / 5 帧 >33ms 的抖动来源待定（排序 worker / GC / 包围盒补算）。
- 浏览器版对比调研：见 `docs/perf/supersplat-3.3.0-对比调研.md`（含上游 v3.3.0 源码出处与 P0/P1/P2 差异清单、
  量测方案与判定阈值）。核心结论：上游 3.3.0（playcanvas 2.22.1）已自带 **GPU 投影 + 紧凑化 + GPU 基数排序
  + indirect draw**，官方博客 20M 一档 WebGL2 44.9ms(22fps) / WebGPU 10.2ms(98fps) ——
  本机 WebGPU 架构**等价于那一列 WebGL2**（worker CPU 排序 + 每高斯展开 quad），
  所以"换 WebGPU 后端"本身不加速，加速来自把投影/剔除/排序搬进 compute（P0-3）。
  最值得先做的三条：P0-1 框选改 GPU/Worker（1275ms → 目标 ≤300ms）、
  P0-2 停止每帧强制全量 worker 排序、P0-3 交互期降级。
