# 视野角快捷面板"让位"右侧面板（2026-09-22，v3.23.34）

## 问题（用户报的第二个遮挡）

右上角坐标轴下方的快捷面板（视野角 / 显示边界 / 显示网格）是 `#canvas-container` 里的浮动块，
而调色面板、设置面板是同一个容器里的右侧浮动列。两者都用"贴右边缘"定位 ⇒ 调色面板一打开就被快捷面板压住一角。

修前实测（1280×800，`_tmp\diag-color-overlap.cjs`）：

| 元素 | 矩形 [left, top, right, bottom] |
| --- | --- |
| 快捷面板 | `[1046, 146, 1268, 242]` |
| 调色面板 | `[858, 24, 1178, 744]` |

重叠区 `132 × 96 px`（右上角那一块），`overlapColor = true`。

## 方案：`:has()` 让位，零 JS

在 `src/ui/scss/view-quick-controls.scss` 里加一条规则——**只要右侧面板可见，快捷面板就退到面板列的左边**：

```scss
@at-root #canvas-container:has(#color-panel:not(.pcui-hidden)) #view-quick-controls,
#canvas-container:has(#settings-panel:not(.pcui-hidden)) #view-quick-controls {
    right: 434px;   // 102（面板列 right）+ 320（面板宽）+ 12（余量）
}
```

* 两个面板都是 `#canvas-container` 的**兄弟节点**，`:has()` 能直接表达"那两种面板可见时我才挪"，
  不用监听 `colorPanel.visible` / `settingsPanel.visible`，也不引入第二份可见性状态。
* Electron 43 = Chromium 150 ⇒ `:has()`（Chromium 105+）可用。
* 面板一关，规则失效，自动回到坐标轴正下方（`right: 12px; top: 146px`），无需复位逻辑。

### 为什么不是"把面板往下挪"

调色面板是 `top: 50% / translate(0, -50%) / max-height: 90vh`，`24 → 744` 几乎占满 800px 高；
要清开 242px 就得下移 218px，底边变 962px ⇒ 直接出屏。往左让位是唯一两边都完整可见的做法。

## 实测（修后，双后端一致）

| 场景 | 面板 | 快捷面板 | 重叠 |
| --- | --- | --- | --- |
| 调色面板打开 | `[858, 24, 1178, 744]` | `[624, 146, 846, 242]` | 否（水平间隙 12px） |
| 设置面板打开 | `[858, 31, 1178, 737]` | `[624, 146, 846, 242]` | 否 |
| 面板全关 | — | `[1046, 146, 1268, 242]` | —（回到坐标轴正下方，间隙 6px、右边缘差 12px） |

* 视野角滑轨仍为轨道 121px / bar 105px，数字输入框仍隐藏；右侧工具栏 `[1202, 254, 1256, 780]` 仍无重叠。
* 回归：`docs/verify/verify-view-quick-controls.cjs` 扩到 10 条断言（新增"两种右侧面板打开时都不重叠"），
  并**故意让断言依赖面板真的被打开**（`opened` 标志）——否则面板没打开时盒子为 `null`，重叠判断会假通过。
  webgpu / webgl2 各 `failed = 0`。
