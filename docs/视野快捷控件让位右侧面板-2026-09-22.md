# 视野角快捷面板"让位/隐藏"右侧面板（2026-09-22，v3.23.35）

## 问题（用户报的第二个遮挡）

右上角坐标轴下方的快捷面板（视野角 / 显示边界 / 显示网格）是 `#canvas-container` 里的浮动块，
而调色面板、设置面板是同一个容器里的右侧浮动列。两者都"贴右边缘"定位 ⇒ 调色面板一打开就被快捷面板压住一角。

修前实测（1280×800，`_tmp\diag-color-overlap.cjs`）：

| 元素 | 矩形 [left, top, right, bottom] |
| --- | --- |
| 快捷面板 | `[1046, 146, 1268, 242]` |
| 调色面板 | `[858, 24, 1178, 744]` |

重叠区 `132 × 96 px`（右上角那一块），`overlapColor = true`。

## 方案：`:has()` —— 面板打开时**隐藏**快捷面板（用户选定）

先试过"挪到面板列左边"（`right: 434px`，实测也确实不重叠了），但把两个方案摆给用户后，
**用户选了隐藏**：挪过去就不在坐标轴正下方了，而这块面板的全部价值就是"在坐标轴下方随手够到"，两者只能选一个。

最终规则（`src/ui/scss/view-quick-controls.scss`）：

```scss
@at-root #canvas-container:has(#color-panel:not(.pcui-hidden)) #view-quick-controls,
#canvas-container:has(#settings-panel:not(.pcui-hidden)) #view-quick-controls {
    display: none;
}
```

* 两个面板都是 `#canvas-container` 的**兄弟节点**，`:has()` 直接表达"那两种面板可见时我就让开"，
  不用监听 `colorPanel.visible` / `settingsPanel.visible`，也不引入第二份可见性状态。
* Electron 43 = Chromium 150 ⇒ `:has()`（Chromium 105+）可用。
* 特异性 `(3,1,0)` > 基础规则 `#view-quick-controls:not(.pcui-hidden)` 的 `(1,1,0)` ⇒ 不依赖书写顺序。
* 面板一关规则失效，自动回到坐标轴正下方（`right: 12px; top: 146px`），无需复位逻辑。
* 设置面板同样处理：它和调色面板同一列、同样重叠（实测 `[858, 31, 1178, 737]`）。
  若你希望设置面板打开时**保留**快捷面板（改成挪到左边），说一声即可，一行的事。

### 为什么不是"把面板往下挪"

调色面板是 `top: 50% / translate(0, -50%) / max-height: 90vh`，`24 → 744` 几乎占满 800px 高；
要清开 242px 就得下移 218px，底边变 962px ⇒ 直接出屏。

## 实测（修后，双后端一致）

| 场景 | 右侧面板 | 快捷面板 |
| --- | --- | --- |
| 调色面板打开 | `[858, 24, 1178, 744]` | **隐藏**（display:none，盒子为 null） |
| 设置面板打开 | `[858, 31, 1178, 737]` | **隐藏** |
| 两个都关掉 | — | 回到 `[1046, 146, 1268, 242]`（坐标轴正下方，间隙 6px、右边缘差 12px） |

* 视野角滑轨仍为轨道 121px / bar 105px，数字输入框仍隐藏；右侧工具栏 `[1202, 254, 1256, 780]` 仍无重叠。
* 回归：`docs/verify/verify-view-quick-controls.cjs` 共 10 条断言，第 3 条已从"不重叠"改成
  "面板打开时隐藏、关闭后回来"，并**故意让断言依赖面板真的被打开**（`opened` 标志）——否则面板没打开时
  盒子为 `null`，会被误读成"隐藏成功"而**假通过**（这是我第一版踩过的坑）。
  webgpu / webgl2 各 `failed = 0`。
