# 物体识别 / 分割方案探索存档

> 项目：SplatRoom（基于 PlayCanvas SuperSplat v2.31.10 二次开发的 3D 高斯 Splatting 编辑器）
> 模块：seg-lab 物体分割实验台（`SplatRoom/seg-lab/`）
> 作者：摄影师黄Sir
> 存档日期：2026-08-05
> 状态：**方案 A（区域生长 + 图割）已放弃；方案 B（SAM 2D→3D 投影）已落地验证**

---

## 一、背景与目标

在 3D Gaussian Splatting（3DGS）场景里，"识别一个物体并把选中、隐藏其它、导出子模型"是后续做**物体级编辑 / 清理 / 替换**的前置能力。本实验台的目标是在 SplatRoom 内探索并验证一种可行的思路：

- 用户给一个**轻量 2D 提示**（在画面里点一下物体表面，或拖一个框圈住物体）；
- 系统自动把**所有高斯**投影到当前相机屏幕空间；
- 利用**屏幕最小深度**区分"提示命中物体的高斯"和"落在它背后/侧后的背景高斯"；
- 选中 → 隐藏背景 → 可导出选中子集为 `.ply`。

整个探索经历了两条路线：**方案 A（3D 空间区域生长 + 图割）** 与 **方案 B（把 2D 提示投影回 3D 做深度带筛选）**。

## 三、方案 A：区域生长 + 图割（已放弃）

### 3.1 设计思路
- **区域生长**：从用户点击/框选命中的种子高斯出发，用空间近邻（空间哈希网格）+ 颜色/位置相似度做 BFS 扩张，把"连成一片且相近"的高斯聚成一个区域。
- **图割（Graph Cut）**：以区域为节点、相邻高斯对的颜色/位置差为边权，构造能量函数（数据项 + 平滑项），用 min-cut 优化得到分割边界。

### 3.2 探索中暴露的工程问题（与算法本身无关，但反复导致"没反应"）
1. **favicon.ico 404**：浏览器控制台报错被误当成功能故障 → 加内联 SVG favicon。
2. **浏览器缓存旧 JS**：改了代码但页面加载的是旧版脚本 → 用 `?v=N` 破坏缓存 + 把版本号写进 `document.title` 便于肉眼核对。
3. **误用单连通 test.ply**：`?model=test.ply` 是一个稀疏单球，导致"选中全部/极少"假象 → fallback 改内置 `scene.ply`。
4. **运行时改 opacity / scale 不生效**：在 PlayCanvas unified gsplat 管线里，splat 排序 worker 会缓存状态，运行时改 `instance` 的 opacity/scale 写入 GPU 成功但**视觉不变**（sort worker 不改 → 屏幕上还是原样）。尝试 `FADED=-25`、`scale=-30` 都无效。

### 3.3 最终绕过方式
用 **entity 拆分**（把选中高斯和背景高斯拆成两个 `gsplat` entity，切换其 `enabled`）来显隐，彻底绕开 sort worker 缓存。这一步在方案 B 里也被沿用为 `applyVisual()` 的可靠渲染手段。

### 3.4 放弃的根本原因
- 3DGS 是**体积、重叠、无序**的点云式表征，没有显式表面拓扑。区域生长依赖"近邻 + 相似度"在重叠高斯堆里极易越过物体边界，把相邻但不同物体拉进同一个区域。
- 图割的能量项（数据项/平滑项）在 splat 这种软半透明表示上缺乏稳定定义，参数极难调。
- 用户实测反馈"依然没有反应 / 选了 A 反而没了"，综合判断该路线在 splat 数据上不值得继续投入 → 改用方案 B。

## 四、方案 B：SAM 2D→3D 投影（采纳并验证）

### 4.1 核心思想
不去做 3D 空间的区域生长，而是**借用 2D 语义提示**，把问题转化为"屏幕空间 + 深度"的筛选：

> 用户在 2D 画面里指认物体（SAM 风格的 point / box prompt）；我们把所有高斯投影到该 2D 视角，用**逐像素最近深度**标定"被指认物体的表面"，再保留"深度不比该表面落后太多"的高斯，从而把物体从背景里抠出来。

### 4.2 算法步骤（落地实现见 `seg-app.js::runSegmentation`）

**第 1 步 · 投影全部高斯到屏幕空间**
手写 gluLookAt 风格的 view + projection 矩阵（**不信赖** `pc.Mat4.transformPoint` 与 `camera._camera.*Matrix`，详见第五节）：
```
sx[i], sy[i]  = 屏幕像素坐标
depth[i]      = 相机空间线性深度（前方为正），用于前后排序
behind[i]     = 是否在相机后方 / 出 NDC → 直接排除
```

**第 2 步 · 提示命中测试（inside-prompt）**
- 点选：`(sx-cx)² + (sy-cy)² <= r²`（r = 点击半径，默认 24px）
- 框选：`x0<=sx<=x1 && y0<=sy<=y1`

**第 3 步 · 逐屏幕像素记录"命中高斯"的最小深度**
```
step = 2（栅格分辨率）
depthMap[gx,gy] = min(depth[i])  for 所有 inside 的高斯 i
dMinIn / dMaxIn = 命中高斯深度的最小/最大
```

**第 4 步 · 深度带筛选**
```
tolFrac  = 深度容差% / 100      （默认 3%）
band     = (dMaxIn - dMinIn) + sceneRange * tolFrac
选中条件：depth[i] <= depthMap[pixel] + band
```
- `band` 由"命中物体本身的深度跨度" + "整场景深度范围的一小段容差"构成；
- 调大容差 → 多保留物体**后方**的高斯（防边缘漏选）；调小 → 更严格、更干净。

命中结果写入 `mask[]`，再调用 `applyVisual()`（entity 拆分）显隐。

### 4.3 渲染：entity 拆分（`applyVisual`）
- 把 `mask[i]==1` 归入选中 entity、`mask[i]==0` 归入背景 entity；
- 隐藏背景 = 关闭背景 entity 的 `enabled`；
- 导出子模型 = 把选中高斯（含 x/y/z、颜色、scale、rot、opacity）写出为 INRIA 3DGS 格式 `.ply`。

### 4.4 探索过程修复的 5 个深层 bug（关键经验）

| # | Bug | 现象 | 根因 / 修复 |
|---|-----|------|------------|
| 1 | `const canvas` 重复声明 | `Identifier 'canvas' has already been declared` | bindUI 内重复声明 → 移除冗余 |
| 2 | **双透视除法** | 200k 高斯全压到屏幕中心 (640,400)±22px 斑点，点一下"选全部" | 当前 build 的 `Mat4.transformPoint` 已自动除 w，代码又手动除一次 → **改为纯手算 clip math**（`m*p` 后只除 `cw = m[3]x+m[7]y+m[11]z+m[15]`） |
| 3 | **view 矩阵 forward 方向错** | 所有点落到相机后方（cw 极小、出 NDC） | 旧版 forward 朝 +Z；改标准 gluLookAt：`s=cross(f,up)`、`u=cross(s,f)`、`view.z 行 = -f`、`view.w.z = +f·pos` |
| 4 | **right 向量分量写错** | `sx_ = fy` 应为 `sx_ = -fz`（`cross(f,(0,1,0)) = (-fz,0,fx)`）→ 红球投到屏外 x=1543 | 改正为 `sx_=-fz, sz_=fx` |
| 5 | **`GSplatData.calcAabb()` 返回夸张 AABB** | 200k 真坐标 ±3 → halfExtents 70 → fitCamera 把 dist 设成 183，整模型缩成 40px 斑点 | **弃用 calcAabb，改用手动从 px/py/pz 循环算 AABB** |

### 4.5 真实模型加载入口（v13/v14 新增）
- 文件选择 `#fileInput`、URL 加载 `#fileUrl` + 按钮、拖拽 `.ply` 到画面（橙色虚线提示）；
- 引擎一次性 boot（`bootEngine()`），`loadModelFromBuffer()` 切换模型并 `teardownModel()` 销毁旧状态；
- 静态服务器 `scripts/static-server.js`（PORT 3200）。

### 4.6 验证结果（headless puppeteer + Edge + SwiftShader）

## 五、关键技术坑 / 经验总结（通用，可复用）

1. **PlayCanvas 投影一律手算**：`Mat4.transformPoint(v)` 在不同 build 透视除法语义不一；
   `camera._camera.{view,projection}Matrix` 可能是**帧缓存的旧值**，与 GPU 实际渲染不一致。
   最可靠做法是从 `entity.getPosition()` + 目标点 手算 gluLookAt 矩阵（见 MEMORY.md）。

2. **`GSplatData.calcAabb()` 不可信**：当前 build 对手动构造的 GSplatData 返回错误 AABB，
   必须用 `px/py/pz` 循环手算包围盒再 fitCamera。

3. **unified gsplat 运行时改 opacity/scale 不生效**：sort worker 缓存吞掉 → 用 entity 拆分显隐。

4. **浏览器缓存旧 JS**：功能"没反应"先排除缓存 → `?v=N` 破坏缓存 + title 显示版本号。

5. **headless 大模型截图超时**：200k 高斯 swiftshader 单帧 ~5s，`page.screenshot()` 必须带 timeout 并 `.catch(()=>{})`，否则 ProtocolError 卡死。

6. **favicon 404 干扰判断**：加内联 `data:image/svg+xml` favicon。

## 六、如何使用与验证

- 预览页：`http://localhost:3200/seg-lab/?model=scene.ply`（v=14，Ctrl+F5 硬刷新）
- 加载真实模型：文件选择 / URL / 拖拽 `.ply`（INRIA 3DGS 格式：float binary，含 `x y z f_dc_0..2 opacity scale_0..2 rot_0..3`）
- 操作：
  - **点选物体**：左键点表面（蓝圈为提示半径）→ 自动分割并隐藏背景；
  - **框选区域**：左键拖框圈住物体；
  - **视角旋转**：拖拽旋转 / 滚轮缩放 / 右键平移；
  - **深度容差**滑块：调大防边缘漏选，调小更严格；
  - **隐藏背景 / 导出子模型 / 重置** 按钮。

## 八、结论与后续建议

- **结论**：在 3DGS 上做物体识别，"在 3D 空间做区域生长 + 图割"路线因数据特性（体积/重叠/无序、无表面拓扑）难以稳定；**"2D 语义提示 + 屏幕投影 + 深度带筛选"** 路线在真实 200k 模型上已验证可行（36.9ms 选准单物体、0 error），是当前推荐方案。
- **后续可深化方向**：
  1. 引入**真正的 SAM / SAM2 推理**（当前是"屏幕最小深度"近似，无语义），把 2D mask 反投回 3D，精度与边界质量会更高；
  2. 多视角**投票融合**（同一物体在多个相机角投票），解决单视角自遮挡导致的漏选；
  3. 把 seg-lab 的分割结果**回写进 SplatRoom 主工程**的物体选择/分组体系（Group/Link）。
